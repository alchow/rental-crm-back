# Test review — 2026-09-26

Status: point-in-time review and refactoring record, not an architecture reference.

## Refactors applied

- Replaced 40 copies of Supabase discovery/environment setup with
  `configureIntegrationEnv`. Discovery now resolves the database directory from
  the helper's location, without guessing the caller's working directory.
- Replaced 37 equivalent pass/fail reporters and repeated assertion/random-token
  helpers with the existing implementations in `api/test/helpers/integration.ts`.
  Specialized reporters retain their different output requirements.
- Migrated five JSON request wrappers to `createApiClient`. The helper now rejects
  malformed JSON, supports explicit binary responses, and lets missing-key tests
  omit the automatic idempotency header. The incidents PDF assertion now receives
  actual bytes rather than text cast to a byte array.
- Shortened repeated coverage summaries and historical commentary in the refresh,
  email, and tenant-validation suites. Added `api/test/README.md` with the shared
  test pattern and its request/response options.

Example: suite sets local Supabase env → imports the app → shared client sends the
owner JWT and idempotency key → domain assertions inspect the response and DB.
Fixture construction, SQL, scenario ordering, and business assertions remain local.

## Coverage weaknesses fixed

1. **A concurrency suite was absent from CI.** Added the existing rent-adjustment
   suite to `.github/workflows/ci.yml:169`. Its wait assertion now observes
   `pg_blocking_pids` instead of treating a 150 ms delay as proof of blocking
   (`db/test/rent-adjustment-concurrency.test.ts:63`).
2. **The manifest guard could miss an entire new test file.** It previously checked
   only package scripts. It now rejects unregistered standalone files and missing
   script targets; regression specs cover both directions
   (`scripts/check-test-manifest.mjs:45`, `api/test/test-manifest.spec.ts:1`).
3. **Body-size tests exercised only the path matcher.** Added requests through the
   production app at and above both byte limits, including public and account
   routes (`api/test/body-limit.spec.ts:49`).
4. **Security assertions accepted server failures.** Forged system provenance and
   agent legal-hold writes now require the specific HTTP status and SQLSTATE
   (`api/test/comms-email.test.ts:294`, `api/test/comms-evidence.test.ts:932`).
5. **Pagination stubs ignored the requested limit.** The ascending and descending
   tests now require the extra row needed to determine whether another page exists
   (`api/test/cursor.spec.ts:61`).
6. **The local database runner skipped three CI suites.** Added mixed-era audit,
   tenancy-status, and retention checks in CI order. This reproduced an existing
   mixed-era fixture failure: `digest` was not on the connection's search path.
   Qualifying it as `extensions.digest` fixes the test without changing the database
   (`db/test/chain-mixed-era.test.ts:144`, `db/test/run-isolation.sh:103`).

## Further opportunities

- Consolidate the remaining HTTP wrappers after accounting for their deliberate
  differences: binary decoding, `Headers` versus records, custom headers, and
  missing idempotency keys. `documents.test.ts` and `api-isolation.test.ts` are
  examples; replacing them blindly would change what their tests exercise.
- Split large communication suites by behavior, with explicit fixtures passed to
  each group. Keep the manifest entry and runner stable. Start with
  `comms-email-threads.test.ts` and `comms-persona.test.ts`.
- Add fixtures for account-scoped tables exempted from the database isolation
  seed requirement. Empty tables can satisfy the cross-account zero-row check
  without proving that another account's rows are hidden
  (`db/test/isolation.test.ts:73`, `db/test/isolation.test.ts:333`). API integration
  checks provide separate coverage, but do not make that individual check meaningful.
